# GF63 Mic Fix — plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para executar este plano tarefa por tarefa. Os passos usam caixas (`- [ ]`) para acompanhamento.

**Objetivo:** app GTK4 que corrige o microfone interno do MSI GF63 Thin no Linux, distribuído em `.rpm`, `.deb`, pacote Arch e instalador universal, com repositórios apt/dnf próprios assinados e página pública no GitHub.

**Arquitetura:** pacote Python puro (`gf63_mic_fix`) instalado em `/usr/share/gf63-mic-fix/` (ou `~/.local/share/gf63-mic-fix/` no instalador universal) e chamado por um lançador. A correção é um processo `pipewire -c` de usuário, num serviço systemd de usuário próprio, rodando um `filter-chain` gerado pelo app. Tudo que toca o sistema (`pactl`, `systemctl`, `pw-record`, `gpg`, rede) passa por uma camada injetável, para os testes rodarem sem áudio nem rede.

**Tecnologias:** Python ≥ 3.11, PyGObject + GTK 4 + libadwaita 1, PipeWire ≥ 1.0 (módulo filter-chain, `pw-play`, `pw-record`), `pactl`, systemd de usuário, gettext, nfpm, GitHub Actions, `createrepo_c`, `apt-ftparchive`, GnuPG.

**Spec:** `docs/superpowers/specs/2026-11-24-gf63-mic-fix-design.md`. Leia junto com este plano.

## Foco da revisão

1. **Fonte física com outro nome ou em outra placa** (ex.: placa 1, por causa de um dock USB, ou sufixo `analog-stereo.2`): o app acha a fonte pelo codec ALC233 e não pelo nome fixo. Teste na Tarefa 2 (`test_find_physical_source_on_card1`).
2. **O serviço não sobe** (plugin RNNoise removido depois de ligado, conf inválido): "Corrigir" espera a fonte virtual por até 5 s; se ela não aparecer, desfaz o que fez e devolve erro legível. Teste na Tarefa 4 (`test_apply_rolls_back_when_node_never_appears`).
3. **Corrigir duas vezes ou desfazer sem nunca ter corrigido:** nada é sobrescrito e nada quebra. Testes na Tarefa 4.
4. **Sem rede, limite de requisições do GitHub ou JSON estranho na consulta de versão:** a falha é silenciosa (registrada no log), sem travar nem notificar. Teste na Tarefa 7 (`test_check_handles_network_and_bad_json`).
5. **Download adulterado no instalador universal** (assinatura inválida, tar com `../` ou caminho absoluto): rejeita e mantém a instalação atual intacta. Testes na Tarefa 7.

Se o veredito for DEFECT_CONFIRMED, grava `config_dir/diagnosis-ok`.
